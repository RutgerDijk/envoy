# Envoy 2.0 — Token-Optimized Workflows with PR-First Review

> **For Claude:** Use envoy:executing-plans to implement this spec task-by-task.

## Overview

Major upgrade to Envoy that reorders the finalize flow (PR first, then parallel reviews), optimizes token usage across all skills, adds persistent learning from reviews, and introduces hook-based automation for polling and batch processing.

**Priority #1: Token optimization without losing quality.**

## Architecture

### PR-First Finalize Flow

Reorder `/envoy:finalize` so the PR is created early, enabling GitHub CodeRabbit to review in parallel with local reviews. All review agents run as parallel subagents. Every finding (including nitpicks) gets addressed. Claude replies to each GitHub CodeRabbit comment and resolves the thread.

```
1. Docstrings + docs (quick wins first)
2. Push branch + gh pr create
3. Parallel subagents:
   ├── Local CodeRabbit CLI
   ├── Sonnet AI review (spec compliance, TDD, codebase patterns)
   └── Visual review (DevTools) + app health check
4. Background: Poll GitHub for CodeRabbit App comments
5. Merge ALL findings from all sources
6. Address every finding (including nitpicks)
7. Reply to each GitHub CR comment with fix + commit hash → resolve thread
8. Push fixes
9. If new CodeRabbit comments appear → address → push (max 3 cycles)
10. Verify:
    - Tests pass
    - Lint clean
    - Build succeeds
    - Application still running (health check)
    - Zero unresolved PR conversations
11. Wiki sync
```

### Token-Optimized AI Review

Replace single Opus reviewer with a single **Sonnet** agent focused on what CodeRabbit can't do:
- Spec/acceptance criteria compliance
- TDD verification (git log: tests committed before implementation?)
- Codebase pattern consistency (explores surrounding code, not just diff)
- Stack profile: load only the "Common Mistakes" section for changed-file stacks

CodeRabbit (zero tokens from us) handles: style, naming, security, common language mistakes, performance anti-patterns.

Visual review (DevTools, no LLM tokens) handles: UI correctness, console errors, network failures.

**Estimated savings: ~60% cost reduction per review cycle.**

### Token Optimization Across All Skills

**Selective stack loading:**
- Only load stack profiles for files that actually changed (`git diff --name-only`)
- Load only the relevant section (Common Mistakes for review, Best Practices for implementation)

**Lean skill descriptions:**
- All skill descriptions under 30 words (triggers only, no workflow summary)
- Audit existing 23 skills and trim

**Batched stop-phase processing:**
- PostToolUse hook accumulates edited file paths to temp file
- Stop hook runs lint/format once across all files (not per-edit)
- Eliminates N formatter outputs from context window

**Complexity-tier pipeline depth:**
- Trivial changes (docs, config, typos): skip AI review entirely, just lint + CodeRabbit
- Small changes (single file logic): Sonnet review only
- Medium/large changes: full parallel review

**allowedTools restrictions per phase:**
- Review subagents: Read, Grep, Glob only (prevents accidental edits)
- Implementation agents: full tool access
- Verification: Read, Grep, Glob, Bash only

**Async hooks for non-critical operations:**
- Learning extraction: async, no context pollution
- Cost tracking: async JSONL logging
- Only blocking hooks: config protection, verification gates

**Dynamic context injection:**
- Mode-specific context fragments (review.md, implement.md, research.md)
- Swap in/out based on current phase instead of loading everything

### Hook System

**New hooks:**

| Hook | Type | Trigger | Action |
|------|------|---------|--------|
| `post-pr-poll` | PostToolCall | `gh pr create` | Start background polling for GitHub CodeRabbit comments |
| `post-edit-accumulator` | PostToolUse | Edit/Write on code files | Append path to temp file for batched processing |
| `stop-batch-lint` | Stop | End of response | Run lint/format once across all accumulated files |
| `config-protection` | PreToolUse | Edit/Write on config files | Block modifications to linter/formatter configs |
| `cost-tracker` | Stop (async) | End of response | Log token usage to JSONL metrics file |
| `learning-extractor` | Stop (async) | End of response (if review session) | Extract patterns from review findings |

**Hook profiles:**
- `minimal` — Only config-protection and cost-tracker
- `standard` — All hooks (default)
- `strict` — All hooks + additional verification gates

Controlled via environment variable: `ENVOY_HOOK_PROFILE=minimal|standard|strict`

### Memory & Continuous Learning

**Post-review learning loop:**
1. After each review cycle, async Stop hook collects all findings
2. Categorize: recurring (seen 2+ times) vs one-off
3. Recurring patterns saved to `memory/review-learnings.md` with:
   - Pattern description
   - Times seen
   - Stack/file type affected
   - Fix template
4. Next review cycle loads learnings FIRST → Sonnet checks for known patterns before external review
5. Patterns that stop appearing after 5 reviews get archived (the team learned)

**Cost tracking:**
- JSONL log at `~/.claude/metrics/envoy-costs.jsonl`
- Per-session: model, tokens, estimated cost, phase (review/implement/brainstorm)
- Enables optimization decisions based on actual usage data

### Verification Loop

After addressing all findings:
1. Run tests (`dotnet test`, `npm test`)
2. Run lint (`npm run lint`)
3. Run build (`dotnet build`, `npm run build`)
4. Health check: verify application is still running (HTTP ping or process check)
5. Check: zero unresolved PR conversations (`gh api` for review threads)
6. Check: no new CodeRabbit comments since last push
7. If new comments appeared → address → push → re-verify (max 3 cycles)
8. After 3 cycles with remaining issues → escalate to user
9. Only claim "ready for human review" with evidence (test output, build output, zero-comments proof)

### Parallelization & Subagent Orchestration

**Review parallelization (finalize):**
- 3 subagents in parallel: Local CR, Sonnet AI review, Visual review
- Background non-blocking poll for GitHub CodeRabbit
- Each subagent gets clean context (no implementation bias)
- Findings merged after all complete

**Execution parallelization (executing-plans):**
- Dependency-aware task graph from spec
- Independent tasks dispatched as parallel subagents in worktrees
- Fresh Sonnet reviewer per task (author never reviews own work)
- Wave-based: run independent tasks in parallel, sync between waves

**Subagent prompt optimization:**
- Pass context via files (spec path, diff path), not inline in prompt
- Restrict tools per phase (read-only for review, full for implementation)
- Complexity-tier: trivial tasks skip review, small tasks get light review

### Config Protection

PreToolUse hook blocks modifications to:
- `.eslintrc*`, `eslint.config.*`
- `.prettierrc*`, `prettier.config.*`
- `biome.json`
- `.editorconfig`
- `tsconfig.json` (warn only, don't block)

Forces Claude to fix source code rather than weaken the linter. This is especially important during autonomous review-fix loops.

### Task 21: Iterative retrieval for review subagents (Medium priority)

**Files:**

- Create: `contexts/iterative-retrieval.md`

**Steps:**
1. Create `contexts/iterative-retrieval.md` describing the retrieval protocol:
   - **Cycle 1:** Read the diff, identify files that the changed code depends on or is related to (imports, callers, shared types, adjacent files in same module)
   - **Cycle 2:** Read those files, score each for relevance (0-1.0 scale: 0 = unrelated, 0.5 = tangentially related, 0.7 = directly related, 1.0 = critical dependency)
   - **Cycle 3:** If fewer than 3 files scored ≥ 0.7, follow one more hop (files referenced by the files from cycle 2). Score again.
   - **Stop condition:** 3+ files with relevance ≥ 0.7, OR 3 cycles completed (whichever comes first)
2. Update Layer 1 Sonnet AI review prompt in `layered-review/SKILL.md`:
   - Replace "read the diff" instruction with iterative retrieval protocol
   - Agent reads `contexts/iterative-retrieval.md` for the protocol
   - Agent reports which files it retrieved and their relevance scores
   - Review findings now include codebase context (not just diff-only observations)
3. Keep constraints: Sonnet model, Read/Grep/Glob only
4. Commit: `git commit -m "feat(skills): iterative retrieval for codebase-aware AI review"`

### Task 23: De-sloppify cleanup pass (Low priority)

**Files:**
- Create: `skills/cleanup-pass/SKILL.md`

**Steps:**
1. Create skill that runs as a **separate fresh agent** after implementation, before review:
   - Agent receives ONLY the diff (`git diff main...HEAD`) — no implementation context
   - Agent has full Edit/Write access
   - Focus: identify and remove common AI-generated slop
2. Slop categories to remove:
   - **Unnecessary defensive checks:** null checks on values that can't be null, try/catch around code that can't throw, redundant type guards
   - **Over-engineering:** abstractions for one-time operations, premature interfaces/generics, feature flags for non-optional features, backwards-compat shims for code that was just written
