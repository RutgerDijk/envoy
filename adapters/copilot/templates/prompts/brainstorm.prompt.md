# Brainstorm

Turn the user's idea into a fully-formed design and implementation plan, then produce a spec document and GitHub issue.

## Phase 1: Understand the Idea

1. Check the current project state: recent commits (`git log --oneline -10`), existing docs in `docs/plans/`, and relevant source files.
2. Ask clarifying questions **one at a time**. Prefer multiple-choice questions. Focus on:
   - What problem does this solve?
   - Who uses it?
   - What are the success criteria?
   - What is out of scope?
   - Which parts of the codebase are affected?

Do not move to Phase 2 until you have clear answers.

## Phase 2: Explore Approaches

1. Propose 2–3 different approaches with trade-offs.
2. Lead with your recommended option and explain why.
3. Wait for the user to confirm an approach before continuing.

## Phase 3: Present the Design

Present the design in **sections of 200–300 words**. After each section, ask: "Does this look right so far?"

Cover:
- Architecture and key components
- Data model changes
- API surface (endpoints / props / types)
- Error handling strategy
- Testing approach
- Deployment considerations (if any)

Revise based on feedback before creating artifacts.

## Phase 4: Create the Spec Document

Save to `docs/plans/YYYY-MM-DD-<topic>.md` where topic is a short kebab-case name. Replace YYYY-MM-DD with today's date.

```markdown
# <Feature Name>

> **For Copilot:** Use the `/execute-plan` command to implement this spec task-by-task, following TDD.

## Overview

<2–3 sentence description>

## Architecture

<Technical approach, key decisions, components involved>

## Acceptance Criteria

- [ ] Criterion 1
- [ ] Criterion 2

---

## Implementation Plan

**Execution Strategy:** `parallel` | `batch` | `sequential`

<Rationale for chosen strategy>

### Task 1: <Component Name>

**Files:**
- Create: `exact/path/to/file.ext`
- Test: `tests/exact/path/to/test.ext`

**Steps:**
1. Write failing test
2. Run test — expect FAIL
3. Implement minimal code
4. Run test — expect PASS
5. Commit: `git commit -m "feat(scope): description"`

...

---

*Generated by Envoy*
```

### Task Granularity Rules

Each task = one logical unit (2–5 minutes to implement):

| Good | Bad |
|------|-----|
| "Add User entity with Id, Email, Name" | "Implement user management" |
| "Add CreateUserAsync to IUserService" | "Add service layer" |
| "Add POST /api/users endpoint" | "Build the API" |

Every task must include a test file. TDD is non-negotiable.

### Execution Strategy

- **parallel** — Tasks with no dependencies (different files, independent concerns)
- **batch** — Phased work (model → service → controller), with checkpoints between batches
- **sequential** — Tightly coupled changes where each step depends on the previous

## Phase 5: Create Feature Branch and Push Spec

```bash
TOPIC=$(echo "<feature-title>" | tr '[:upper:]' '[:lower:]' | tr ' ' '-' | tr -cd '[:alnum:]-')
git checkout -b feature/$TOPIC
git add docs/plans/
git commit -m "docs(plans): add spec for $TOPIC"
git push -u origin feature/$TOPIC
git checkout main
```

## Phase 6: Create GitHub Issue

```bash
gh issue create \
  --title "<Feature Name>" \
  --body "$(cat <<'EOF'
## Summary

<2–3 sentence description>

## Linked Spec

[View full spec](https://github.com/<owner>/<repo>/blob/feature/<topic>/docs/plans/YYYY-MM-DD-<topic>.md)

## Feature Branch

\`feature/<topic>\` — spec is committed here, ready for implementation

## Quick Start

\`\`\`
/pickup <issue-number>
\`\`\`
EOF
)"
```

Output the issue URL when done.
